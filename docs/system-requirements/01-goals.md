# 01 目标

## 最终目标

1. **人驱动 MIB 演化，MIB 保证代码按 DNA 实现。** 人在 ODAAF 里改本体；本体导出为 MIB；代码生成和校验以 MIB 为准。人不直接改代码里的知识。
2. **一个统一的物自体空间。** 各领域的客观对象（PCB 实物、工序、事件……）汇集在共享的 N 层里，所有视图（CNC、XML、PCB、工程索引……）都抽象自它。计算机和 LLM 能做的是汇集多来源、求得主体间一致的经验对象，见 [03-spaces.md](03-spaces.md)。
3. **可视化是可交互的前提。** 看不清就改不对。呈现必须让人一眼看出：现在焦点在哪、这一层由什么组成、两个视图在哪里对上、哪里有缺口。
4. **参谋体系，不是指挥体系。** 系统给人提供位置、证据和建议；决定由人做。所以主键必须人能读：OID 而不是 UUID，见 [05-coordinates.md](05-coordinates.md)。

## 各部分的职责

| 部分 | 职责 | 不做什么 |
|---|---|---|
| ODAAF（OrcheEditor） | 主编辑器：编辑本体、校验、2.5D 呈现、导出 MIB 与场景 | 不做全局 3D 漫游 |
| OMStudio | 只读 3D 总览：同屏看全部宇宙，找到区域后跳回 ODAAF | 不编辑 |
| OrcheMind | 推理；为每个对象给出全局位置向量（Q 的位置） | 不定义本体 |
| 世界文件（`*.odaaf`，物自体表） | 承载客观事实与规则（裁判） | 不含任何视图的编号或格式 |
| 视图文件 | 各格式自己的对象，经 `abstracted_from` 落到世界 | 视图之间不直接连线 |

## 成功的标志

- 换掉或丢失一套视图映射后，仍可从世界文件重建它（世界是兜底锚点）。
- 另一个 PCB 应用只导入世界文件，就能复用全部客观事实和规则。
- 任何对象在 ODAAF、OMStudio、OrcheMind 三处用同一个 OID 找到，位置一致（同一版本内）。
- 裁判对现有数据发现数为 0；新加的违规边会被指出，并给出修法。
