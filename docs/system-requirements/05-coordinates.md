# 05 主键与坐标

## OID 是永久主键

**决定：恢复原始设计，以 OID 为唯一主键，并保证它全局唯一。**

理由：

- OID 人能读、能口述、能按层级理解（"863 模块的 3 号分支第 80 条"），UUID 不能。系统是参谋体系，主键要服务于人。
- OID 的代价是要统一分配。这个代价只付在"模块"一级，一次登记即可。

做法：

- 规范形 `私有根.2.模块弧.分支.弧`，例 `1.3.6.1.4.1.55555.2.864.1.7`。分支：类 1、数据属性 2、关系 3、术语 4、动词 5、结构 6、规则 7、规则绑定 8、四因角色 9。
- 每个 `.odaaf` 文件占一个模块弧，登记在数据仓库根的 `modules.registry.xml`（862 BZOX Z 补正、863 Omron 视图、864 PCB 世界）。模块弧不重复，OID 就全局唯一。这正是"文件表 + 文件前缀"的方案，只是前缀不由文件名换算，而是登记分配——文件改名、移动都不影响它。
- ODAAF 加载时从文件目录向上找登记表并校验：未登记、弧与登记不符、两个已加载文件同弧，都报警告。新文件取下一个空弧。
- **永久**：弧一经分配永不复用；删除的弧写进 `RetiredArcs`。对象分裂时得到一个或两个新 OID，旧 OID 退役，不改给别人。
- UUID 仍保留，作机器侧的冗余身份（导入合并、跨工具对账），不作主键。

旧形 OID（`私有根.模块弧.1.分支.弧`，例 `1.3.6.1.4.1.55555.863.1.3.80`）在加载时规范化为新形；两种写法指同一个对象。

## 位置向量不是主键

OID 永远不变；位置向量会变。它由 OID 派生，同一本体版本内固定，每次进化可微调或突变——这是我们一直在优化的部分。

```
位置向量(OID, 版本) = [ 谐波块(OID, 该版本的动词先验角) ; 布局块(该版本的星系布局) ]
```

### 谐波块

- 8 个谐波，每个取 cos 与 sin，共 16 个实数。
- 第 0 谐波 = 锚动词的先验角 \(\theta\)。先验角按版本调整（`harmonic_priors.json`）。
- 第 \(k\) 谐波相位 \(\varphi_k = \theta + 2\pi k\,\alpha(\text{OID})\)，用来把同动词的节点分开。

**坐标方案**（`coord_scheme`，写在每个版本的 `ontology.json`；缺省为 1）：

| 方案 | \(\alpha(\text{OID})\) | 状态 |
|---|---|---|
| 1 | 企业弧（862 或 55555）之后各段按 100 进制打包，除以 \(10^6\) | v001、v002 已用；保持不变，以守住"同一版本内固定" |
| 2 | 先规范化 OID，再取 SHA-256 前 8 字节 / \(2^{64}\) | 新版本用 |

方案 1 的问题：段值 ≥ 100（模块弧 863、弧号 100 以上）会进位，不同 OID 可能打包成同一值；两个模块的锚也不一致。方案 2 只依赖规范 OID，所以改名、移文件、换存储格式都不影响。

### 布局块

ODAAF 的星系布局给出环面坐标 (\(\varphi\) 宇宙方位角, 深度, \(\theta\) 环内角) 和知识层 (层号, 归一化营养级)。这一块完全按版本，由场景导出（[06-3d-overview.md](06-3d-overview.md)）提供。

## 给 OrcheMind 的 Q 位置契约

- 键：规范 OID。
- 值：`{ "oid", "version", "coord_scheme", "harmonic": [16 个实数], "torus": [φ, depth, θ], "layer": 0|1|2, "level": 0..1, "weight": 0..1 }`。
- 同一 `(oid, version)` 在 ODAAF、OMStudio、OrcheMind 三处数值一致。
- 版本升级时，OrcheMind 用 OID 对齐新旧两份坐标，测量每个对象的位移；位移大的列为"突变"，交人审阅。
