# 03 空间

## 三层：X / N / V

| 层 | 名字 | 内容 | 例子 |
|---|---|---|---|
| X | 先验对象（物自体） | 只有身份，没有属性 | `cls-pw-x-board` |
| N | 经验自然（物自体表） | 物理事实、工序、规则 | 孔、焊盘、钻刀、钻孔事件 |
| V | 视图 | 各格式自己的对象 | CNC 刀、XML 刀具、PCB 窗、工程索引 |

动词分三个域，不混用：

- 经验域（N 内部、V 内部）：`part_of`、`causes`、`participates_in`、RCC8 …
- 表示域（V → N）：`abstracted_from`
- 界限域（N → X）：`appearance_of`

详见 [`noumenon-phenomenon-projection`](../../.cursor/skills/noumenon-phenomenon-projection/SKILL.md)。

## 宇宙

一个宇宙是一套视图（或世界本身）的全部对象。当前有五个：CNC、XML、PCB、工程索引（四个视图）和 PCB 世界。

- 识别方法：父结构列出至少两个根，每个子结构的 `layer` 各不相同。被至少两个宇宙经 `abstracted_from` 指向的那个，就是世界。
- 顺序：与父结构同一 OID 分支的在前，然后按弧号。

## 统一的物自体空间

康德的 X 不可知，这对任何有限的认识主体都成立，计算机和 LLM 也不例外。它们能做的是：汇集许多来源，得到主体间一致的经验对象——也就是 N 层，相当于波普尔的"世界 3"。

所以"统一的物自体空间"实现为**跨领域共享的 N 层**：

- `pcb-world.odaaf` 是它的第一个区域。以后其它领域各有世界文件，按同样方式导入，彼此可以再导入。
- 世界文件有两个用途：其它 PCB 应用直接复用；映射改变或丢失时，作为兜底锚点。
- 在一个视图里工作时，不必往外看：视图只需知道自己的叶子抽象自哪片世界叶子。

## 视图之间不直接连线

两个视图的对象要"对上"，就让它们抽象自同一片世界叶子，不在视图之间画边。

- 两端有共同世界叶子 → 这条对应边多余，可删。
- 两端世界叶子不同 → 它们之间的关系是客观事实，应写在世界里（例：孔与焊盘部分相交 `hole-po-pad`）。
- 一端没有 `abstracted_from` → 先给它补上。

Omron 1.10.0 已按此删掉全部旧"对应"边；两类刀具都抽象自世界的钻刀。

## 多文件与只读

- 视图文件用 `<odaaf:Imports>` 导入世界文件。导入项只读：不分配身份、不保存、不进 MIB 和切片。
- 删掉的弧登记在 `<odaaf:RetiredArcs>`，永不复用。
- 每个文件的模块弧登记在数据仓库根的 `modules.registry.xml`，保证 OID 全局唯一（见 [05-coordinates.md](05-coordinates.md)）。

## 裁判与运动员

规则是世界里的声明式数据（裁判），视图是运动员。规则用 `implementationBinding` 指名受信任的执行器（`RefereeCheck`）；没有绑定的规则如实报"未执行"。

| 规则 | 范围 | 状态 |
|---|---|---|
| `abstraction-targets-nature`：`abstracted_from` 只能指向 N 层 | 世界 | 已执行 |
| `peers-meet-in-world`：视图之间的对应边要么删、要么写进世界 | 世界 | 已执行 |
| 孔径为正、背钻在孔内、残桩非负 … 共 8 条 | 自然 | 待实例数据 |
