# 以物自体表为锚的训练与使用

**结论**：OrcheMind 训练位置时，只训练物自体本体（世界文件的 N 层）。CNC、XML、PCB 等视图里的本体，位置锚定在它所抽象自的世界叶子上，不单独训练。

这条结论来自 2026-10 的分层工作：世界文件是超集；视图之间不直接连线，只经 `abstracted_from` 落到世界；裁判对现有数据的发现数为 0。既然所有视图都在世界里相遇，位置也只需要在世界里算一次。

相关需求：[system-requirements/03-spaces.md](system-requirements/03-spaces.md)（X / N / V 三层）、[system-requirements/05-coordinates.md](system-requirements/05-coordinates.md)（OID 是主键、位置向量按版本）。操作要点写在 skill [`orchemind-world-anchored-training`](../.cursor/skills/orchemind-world-anchored-training/SKILL.md)。

## 为什么只训练世界

| 好处 | 原因 |
|---|---|
| 计算量小 | 训练集大小是世界叶子数（PCB 世界现在 17 个类），不是所有视图类的总和（现在 100 多个，而且还会增加） |
| 位置稳定 | 视图来来去去，格式会换；实物板的孔、焊盘、铜层不变。锚在不变的东西上，位置就不漂 |
| 结果能长期保存 | 世界坐标按 `(规范 OID, 世界版本)` 存一次；视图只存"我抽象自哪个世界 OID"，不存向量 |
| 新视图零训练 | 以后加 Gerber、ODB++ 或别的机台格式，只要写 `abstracted_from` 边，不必重训 |
| 翻译即查表 | CNC→XML 的对应，就是"两边抽象自同一个世界 OID"；不需要在视图之间学映射 |

## 三层各自怎么处理

| 层 | 有没有位置 | 怎么得到 |
|---|---|---|
| X（先验对象） | 没有 | 只有身份。不可认识，所以不进训练，也不给坐标 |
| N（世界，经验对象） | 有，**训练对象** | 在世界图上训练；只用世界内的边（`part_of`、`causes`、`participates_in`、RCC8 等） |
| V（视图） | 有，**派生** | 世界锚点的位置 + 很小的视图偏移 |

### 视图叶子的位置

```text
pos(视图叶子, 版本) = pos(世界锚点, 版本) + ε · offset(视图模块弧, 视图叶子 OID)
```

- 世界锚点 = 视图叶子 `abstracted_from` 指向的世界叶子。
- ε 很小，只让同一个世界叶子上的几个视图叶子不重叠；它们看起来围着锚点。
- offset 用规范 OID 的哈希算（谐波方案 2），所以不训练、可重算、跨工具一致。
- 一个视图叶子抽象自多个世界叶子时，锚点取这些世界叶子位置的加权中心。权重按抽象边的说明给；没有说明就均分。

### 没有锚点的视图叶子（私有叶子）

翻译模式里淡化显示的那些（例：CNC→XML 时 14 个）。

- 位置取它在本视图内最近的、有锚点的邻居，再加偏移；标为"未锚定"，置信度低。
- 私有叶子是"世界还缺一个叶子"的候选。是否在世界里新建叶子，由人决定；AI 只提出候选。

## 训练权重：认可度

一个世界叶子被几个视图抽象到，就是它的认可度（[02-knowledge-layers.md](system-requirements/02-knowledge-layers.md) 的"权重"）。

- 认可度高的世界叶子（例：焊盘被 XML 和 PCB 都抽象到）是"过孔枢纽"，训练时给更大权重，位置更要稳。
- 只被一个视图抽象到的世界叶子 = 翻译缺口，不影响训练，但要列出来交人审阅。
- 层与权重分开：认可度只改训练权重，不改知识层。

## 版本与进化

- 世界每升一版，重训世界坐标；视图坐标全部按公式重算，不训练。
- 新旧两版用 OID 对齐，测量每个世界叶子的位移；位移大的列为"突变"，交人审阅。
- 世界叶子分裂或合并：按迁移表把旧 OID 映射到新 OID，挂在旧 OID 上的视图锚点跟着迁移。旧 OID 退役，不复用。
- 视图改了、丢了映射：回到世界叶子重新找锚点。世界是兜底。

## 存储约定

```text
data/world_coords/<世界 URI 末段>/<世界版本>.json
  { "world": "urn:odaaf:world:pcb", "version": "1.3.0", "coord_scheme": 2,
    "nodes": [ { "oid": "1.3.6.1.4.1.55555.2.864.1.7", "vector": [...], "weight": 0.8 } ] }
```

- 键是规范 OID，不是 id、不是 UUID。
- 视图坐标不入库；需要时由 ODAAF 场景导出（`.scene.json`）或 OrcheMind 按公式算出来。
- V03 及以前的快照不改。世界坐标从下一个工程 DNA 版本开始使用。

## 使用时的流程

```text
问题（Q） → 找到它属于哪个视图叶子或世界叶子 → 取世界锚点
        → 在世界空间里找邻居、路径、规则 → 再投回目标视图（经 abstracted_from 反查）
```

例：问"这个 CNC 刀在 XML 里叫什么"→ CNC 刀抽象自世界钻刀 → 世界钻刀被 XML 刀具抽象到 → 答 XML 刀具。不需要在 CNC 和 XML 之间学任何东西。

## 不做的事

- 不在视图之间训练映射；不恢复 `corresponds` 边。
- 不给 X 层坐标。
- 不让训练出的位置授权任何动作：位置只用来检索和提出候选，授权仍由确定性的规则与能力检查决定。
- 不用位置向量当主键；主键永远是 OID。
