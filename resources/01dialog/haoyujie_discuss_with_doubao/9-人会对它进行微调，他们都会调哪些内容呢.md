# 一、千问开源包发布的是**一整个文件夹，不是单个文件**（Hugging Face标准格式，现在绝大多数开源LLM都用这套）
> 千问（Qwen）官方开源放出来的是一套文件集合，放在同一个目录下。**权重本身会拆成多个分片文件**，原因是大模型权重太大，单文件容易超过存储/上传限制，并且支持分片加载。

## 目录内文件清单（HF标准，Qwen2/Qwen2.5都是这套）
```
Qwen2.5-7B-Instruct/
├── config.json                # ✅ 模型架构定义（最重要的配置）
├── generation_config.json      # 推理生成默认参数：temperature、max_new_tokens等
├── tokenizer_config.json       # tokenizer配置，特殊token（<|endoftext|>等）
├── tokenizer.json              # BPE分词核心规则
├── vocab.json / merges.txt     # 词表
├── chat_template.json          # 对话模板，定义用户/assistant怎么拼接prompt
├── model.safetensors.index.json# ✅ 分片索引文件：记录每个张量在哪一个分片文件里
├── model-00001-of-00004.safetensors
├── model-00002-of-00004.safetensors
├── model-00003-of-00004.safetensors
├── model-00004-of-00004.safetensors
└── README、LICENSE等说明文件
```

### 核心说明
1. **`.safetensors`**：现在千问官方默认的权重存储格式，**Hugging Face生态的事实标准**，替代旧的`.bin/.pt`。
    - 只存张量，**不执行Python代码**，解决老torch pickle的安全漏洞；支持内存映射，按需加载张量。
    - 里面存储的就是全部神经网络权重：`W_q,W_k,W_v,W_o`、MLP的`w_up/w_gate/w_down`、LayerNorm权重、词嵌入embedding矩阵等。
    - 7B BF16大约14GB，拆成4个分片，加载器依靠`model.safetensors.index.json`把分散分片里的张量重新拼成完整模型。
2. **config.json**：描述Transformer结构：层数、头数、隐藏维度、词表大小、RoPE参数、上下文窗口大小。**没有这个文件，光有权重，程序不知道怎么把张量组装成网络**。
3. Tokenizer整套文件：和模型权重是分开的。负责把文本转token id，没有它，模型无法接收文字输入。

> 还有另一种流行格式：**GGUF**（llama.cpp用），不是官方原生发布，是社区把HF的safetensors转出来，**可以打包成单个gguf文件**，适合本地CPU推理，网上很多本地跑千问的工具用这个。

## 格式有没有标准？
- **HuggingFace Transformers格式（safetensors+json配置）：是大模型社区的事实工业标准**，Qwen、Llama、Mistral、Yi全部兼容这套。
- 不是ISO那种正式国标，但是生态统一；`transformers`、`vLLM`、`SGLang`、`TransformerLens`全部可以直接读取这套目录。
- GGUF是llama.cpp生态的独立标准，主要面向本地轻量化推理。

# 二、千问微调的时候，大家一般调哪些内容？
分两大类：**全参数微调** 和 **轻量微调（LoRA/QLoRA，90%普通人做微调都是这个）**

## 1）全参数微调（Full Fine-tune）
**更新模型全部权重**：embedding、所有层的QKV投影、attention输出、MLP全部矩阵、layernorm全部参数。
- 优点：能力改造上限最高；
- 缺点：显存巨大，7B BF16全参微调，需要几十GB显存，成本很高；
- 用途：持续预训练CPT（灌入大量领域新知识）、大规模SFT。

## 2）LoRA / QLoRA（最常用，社区微调千问首选）
**冻结原始千问全部权重不动，只新增少量低秩矩阵（LoRA适配器）**，训练这些新增小矩阵。
> 原始大权重只读，不修改。训练完得到一个很小的LoRA文件（几十MB~几百MB）。推理时动态合并，或者在线叠加。

### Qwen做LoRA一般瞄准这些模块（target_modules）
- `q_proj`：Query投影矩阵（最核心）
- `k_proj`：Key投影矩阵
- `v_proj`：Value投影矩阵
- `o_proj`：Attention输出投影
- `w_up, w_gate, w_down`：MLP三层矩阵（很多任务会加上）

> 含义：只在注意力QKV和MLP通路增加低秩旁路，修改模型**信息提取、表达**的行为，不改动原始基础权重。

### 还有一些小众微调方式
1. **AdaLoRA**：动态调整LoRA秩，自动分配参数预算；
2. **Prefix Tuning / Prompt Tuning**：不修改权重，只训练一串虚拟前缀token，适合轻量任务；
3. **DPO（偏好微调）**：不是教“怎么回答”，而是训练偏好，区分好回答/坏回答，**可搭配LoRA**，现在对话模型常用。

## 微调能改什么能力？
- SFT监督微调：改输出风格、固定格式、特定任务（写代码、合同、客服话术）；
- CPT持续预训练：灌入新领域知识库，让模型学会新知识；
- DPO偏好微调：减少幻觉、对齐人类偏好、改掉拒绝回答的倾向。

> 重点区分：**微调 ≠ 修改推理时的中间张量（前面TransformerLens那种激活干预）**
- 微调：**修改权重文件，永久改变模型本身，保存下来，下次加载模型自带这个变化**；
- TransformerLens的hook干预：**单次推理临时修改张量，权重文件不变，跑完就消失**。

# 三、一个容易混淆的关键点
✅ 官方发布的权重 = **模型的固定参数（W矩阵）**，是模型“学到的知识”；
✅ TransformerLens抓的q/k/v/残差张量 = **推理过程中动态计算出来的中间状态，每次输入不同prompt就不一样**；
权重是静态存储在safetensors；张量是推理时在GPU显存实时生成。

# 四、极简总结
1. 千问开源包是**文件夹**，里面一堆json配置 + 多个分片`safetensors`权重文件，由索引文件把分片串起来；
2. 这套HF+safetensors是现在LLM社区通用事实标准；GGUF是社区转换后的单文件轻量化格式；
3. 微调主流是LoRA：冻结原始权重，只训练QKV/MLP上新增的低秩矩阵；土豪/大算力场景才做全参数微调；
4. 微调改动**权重**（永久）；前面TransformerLens是临时改动**推理中间张量**，二者完全不是一回事。
