# OrcheMind 开发结论

来源：[豆包讨论《TransformerLens 工具讲解》](https://www.doubao.com/thread/x7LjAaFOZSZdsmuA9)  
离线文稿：`resources/01dialog/TransformerLens工具讲解 - 豆包.html`  
整理日期：2026-09-27  
状态：讨论结束，决定开始开发。当前只做 V01 裸图，不进入向量与训练。

## 决定

项目定名为 **OrcheMind**。

- **Orche** 取自希腊语 Arche（ἀρχή），始基、本原、第一原理。拼写改动是为了避开 Arche 相关项目重名，也避开程序员习惯的 `out/` 输出目录。
- **Mind** 指可控的本体心智，不是模仿对话的大模型。

口号：

> 以始基本体为根，进化迭代为体，对齐通用大模型为用。

一个人开发。大模型只做推理。本体按生物进化的方式向前长：每一代结构冻结、快照留存，下一步只做增量，不从头重算，也不推倒上一代。

## 讨论如何走到这里

讨论从「能不能像调试器一样看大模型每一层内存」开始，最后落到「自己建一套人能控制的本体，再和大模型对齐」。中间有过几条被放下的支线，下面只保留改变了设计的转折。

### 1. 能看到的是带语义的张量，不是全局地图

网上拆解千问一类开源模型，用的是机理可解释性工具，主力是 TransformerLens，同类还有 nnsight、TorchLens。它们在前向计算的模块出入口挂钩子，把残差流、注意力、Q/K/V 拷出来，并标上层、头、token 位置。这不是虚拟机逐字节记录全部显存。全内存回放对大模型不实用，也没有层语义。

由此钉住三件分开的事：

- 发布出来的权重是 **W**：生成 Q、K、V 的矩阵，外加配置、分词器、分片 safetensors。运行时的 Q、K、V 是「输入 × W」算出来的，每次 prompt 都不同，不在权重文件里。
- **RoPE 位置**是推理时按公式算的相位，不占一份可查询的参数，也不存在偏置 b 那种「地球经纬度文件」。
- **微调改权重，永久生效**；TransformerLens 的 hook 只改一次推理的中间张量，跑完就消失。二者不是一回事。LoRA 是基座之上的增量，发布时不自带那份原始基座。

残差流是层与层之间唯一的主干草稿。上层概念（猫仍是哺乳动物）留在这份草稿里，靠旁路相加传下去，不是另存一张静态地图。机理可解释性能对**某一次 prompt**找激活热区、做干预，不能把任意问题反查到一张固定全球坐标上。同一个词在不同句子里不是同一个点。

这次讨论里更新过的认识是：Transformer 比 RNN 强在一次看到整段上下文，但地图仍是本次输入上临时组装的。高维空间是可能性的几何，不是预先放好答案再去查的邮政编码表。训练公司调整的是这套几何的系数，并没有交出一张可检索的全局地图。反向「这个问题落在地图哪一格」因此做不到；做得到的只是单次推理内部的局部定位。

### 2. 位置编码是载波，不是跨会话的实体身份证

RoPE 与傅里叶同源：多个正交频率的正弦、余弦子载波，高频管局部、低频管粗结构。它标记的是**当前这段序列里的第几个 token**。换一次 prompt，同一个代码实体的位置号就变，K 的相位跟着漂，所以原生 KV 缓存不能跨会话、跨版本复用。

通信类比可以保留到这一步：位置像一组载波，把 Q 调制到不同频率上。传递函数不是 RoPE 本身，而是学出来的 W。查表加速 sin/cos 只是实现优化，不改变「位置是相对时序相位」这件事。

各家模型的 RoPE 超参不同，不存在统一的内部位置标准。PIC（把序列内位置和实体身份拆开）仍是研究，没有工业标准。Sourcegraph、Greptile、Graphify、GitNexus 一类系统都刻意不改模型内部位置编码。

因此后来的设计把两套坐标拆开：

- 模型内部 RoPE：只负责同一次注意力里的前后关系。
- 外面的全局实体地址：跨会话、跨版本标记同一个实体。向量索引绑这个地址，不绑 token 序号。

### 3. 要降低的成本，不靠改大模型，靠外面的本体

讨论里短暂看过一个逻辑判定模型（对话中记作 Jev）：它更像单步原子判断，多步推理要外挂循环控制器，链条一长错误会累积。这条线随后放下。

真正要做的是降成本：两次提问即使不在同一个上下文里，也能判断它们是否相关，从而少往大模型里塞文件。Cursor、Codex、Claude Code 这类 harness 只维护有限上下文，没有项目本体。项目的结构、约束、版本谱系丢在外面，每次都要重新喂代码。

用户提出的三层，后来被采纳为总架构：

1. **地址与近似 K/V**：实体的稳定指纹，用于模糊召回。
2. **人能掌控的 Schema / DNA**：项目（以及更一般的本体）如何演化。这一层可读、可版本、可校验。
3. **Harness + 大模型**：在本体划定的空间里问答、生成、执行。大模型是动作执行器，不是本体的主人。

业界已经有中间层的开源原型（GitNexus、Graphiti 的时序图、基于 Tree-sitter 的代码图，经 MCP 接到编码代理）。它们缺的是：统一的跨会话 K/V，以及可执行的架构契约。底层「改 RoPE、让模型内部 K 直接变成全局实体指纹」先不做。工程路线是外挂实体坐标，不改开源大模型。

### 4. Schema 必须正向管住代码，不能只从代码反抽一张图

这是用户纠正后锁定的方向。从 AST 反抽知识图谱，图只是代码的影子：代码怎么写，图就怎么记，不能拦、不能驱动，工程上不够。

要的是双向闭环，而且这条闭环本身不必依赖大模型：

- **正向**：Schema 是单一可信源。人维护实体、关系、不变量；由它生成骨架、接口和测试契约。代码是 Schema 的实例。
- **逆向**：代码变更之后，用静态分析对照 Schema。违约就阻断；合规才把实例状态增量写回，并留下谱系。
- **大模型**：只在 Schema 允许的空间里填逻辑。改 Schema 要走单独授权，不能由模型顺手改掉。

现成组件都只覆盖一部分：Protobuf / Smithy / OpenAPI 管接口与数据；ArchGuard、Nx 管模块边界；Graphiti、GitNexus 只做只读图谱。没有一站式成品。图谱如果要用，只能降成 Schema 的审计视图，不能当权威源。

向量化也按这个次序：Schema 本体保持符号结构。向量只是挂在实体全局 ID 上的检索索引，不是把 Schema 换成一堆浮点数，更不是去绑大模型内部的 token 位置。

### 5. 关系动词要有自己的角度，簇不能被训练冲掉

运行例子是 PCB：通孔穿过焊盘。「穿过」这类动词，希望对应一个稳定的关系算子，类似滤波窗或 RotatE 里的复平面旋转：头实体转一个角度，得到尾实体。这和 RoPE、傅里叶是同一族数学，所以本体空间和大模型空间理论上能对齐。但傅里叶的基是写死的，大模型的基是学出来的，中间要靠投影，不能当成同一个东西。

一万种关系不能在单位圆上均匀乱放，也不能为了“好看”而先聚类再拉成等分——那会丢掉「谁和谁近」。父层能够描述的远近，必须传到子层。做法类比残差：

```text
r_{l+1} = normalize( r_l + F(r_l) )
```

`r_l` 是这个动词自己的角度向量，原样旁路下去。`F` 只允许很小的增量，并且做幅度裁剪，禁止跨扇区跳走。相加之后要拉回单位圆。

这里后来改过一次设计，以最终口径为准：

- 残差里传递的是**单个动词自己的角度**，不是用簇中心替换它。
- **簇原型同时是可检索的独立向量**，供第一层快速定位扇区。它由簇内动词初始化（均值），再平滑更新。簇不只是损失函数里的一句约束。
- 粗分类这一层的布局由人定义。定义本身就是结果，不靠训练“发现”康德范畴或 RCC8。训练只能在这个地基上做微小修正。

总损失分成四项，一起约束个体动词和簇：

```text
L = L_task + L_intra + L_inter + L_alignment
```

- `L_task`：给定实体对，预测关系动词。
- `L_intra`：同簇动词互相拉近。
- `L_inter`：不同簇互相推开，超过阈值才惩罚。
- `L_alignment`：本体动词向量与大模型对应 token 嵌入之间，用可学习投影 `W_align` 对齐。两边维度不必相同。

训练分两段：先只开簇内、簇间损失，把人工扇区固定住；再打开全部损失做对齐。`L_alignment` 会把本体往大模型语义上拉，`L_intra` / `L_inter` 负责拽回来。这是制衡，不是缺陷。

运行时三段：

1. 用簇原型做粗定位，锁住扇区。
2. 在扇区里匹配精确动词。
3. 经 `W_align` 送入大模型，做生成或校验。

没有一份按康德十二范畴标好的公开语料。康德范畴是判断的逻辑功能，不是词表，学术界不会按这张表大规模标注动词。可用的原料是：

- **RCC8**：八个互斥且完备的区域拓扑关系（相离、外切、部分相交、等同、正切真子集及其逆、非切真子集及其逆），自带组合表。适合作为空间簇的公理，不是训练集。PCB 的穿过、贯穿挂在协同性（共存）这一支上，再作为扩展动词。
- **WordNet / WN18RR**：词汇关系与三元组。WN18RR 只有约 11 种关系，适合验证算法，不能当工业谓词库。
- **RotatE**：关系即旋转，数学可借鉴。它的预训练权重按 WordNet 学出来，没有残差、没有簇原型、没有保真损失，**不能直接加载进这套系统**。
- Wikidata、OpenKG、SemRelData、中文 CCL，用来补谓词和句子，再人工归到范畴簇。

同一个动词在不同场景可能是不同范畴（物理上的包含，和集合上的包含），必须拆成两个谓词。二维复平面先够原型用；谓词变多以后再考虑高维复数、多子载波。新簇不由模型自动长出来，新动词由人归入已有簇。

### 6. 算力不够，所以必须进化，不能一次做完

确认现代主流模型都还在「一组基的线性组合」里，没有跳出这套表征，因此「人定义的范畴」和「Transformer」可以共用一套寻址思想。系统最终是三块：

| 块 | 是什么 | 是否训练 |
| --- | --- | --- |
| Schema A | 康德范畴、谓词表、RCC8、初始角度与簇边界 | 不训练。人说了算 |
| Schema B | 残差嵌入、四项损失、簇检索 | 只做小增量，不许推翻 A |
| 大模型 | 开源千问，细粒度理解与生成 | 不微调。只推理、抽 embedding、辅助标注 |

原计划想过用 Protégé、PyKEEN、上千条三元组很快进入训练。用户把顺序改了：一个人、算力有限，第一步不能碰向量。

本体生长固定为两代，训练是更后面的事：

- **第一代**：Node 只是圆，没有端口、没有属性。Link 只表示相连，没有类型、没有方向。先把这张网固化。
- **第二代**：给 Link 加类型和方向，类型逐步接上动词。每一种连到 Node 上的关系，在 Node 上分化出一个端口。旧的拓扑不改，只加字段。

每一步的结果都存下来。错了就回到上一个快照，不重新从零计算。

手头资源按这个约束分配：

- 笔记本 RTX 4060（约 8GB 显存）：图引擎，以及将来的本体小模型。禁止拿它微调 7B。
- 远端 Mac，64GB 统一内存：本体编辑、文本预处理、OWL 校验。不承担 CUDA 训练。
- 已经部署在公网上的千问：同义聚类、生成样本、提取 token embedding。不拥有本体规则，也不做微调。

RotatE 变体即使放到约一万个谓词、复数维 64，训练显存估计在 2GB 以内，4060 将来够用。那是 V03 以后的事。

### 7. 定名

候选里出现过 OntoEvolve、NoesisOnto、ArcheMind、SelfOnto、SoloSchema。用户选中的是 ArcheMind 这一支。助手一度听成 OutMind。Out 有「跳出黑箱、从外部先验定义规则」的意思，但不能用作前缀，因为 `out` 在工程里就是输出目录。

二者合成 **OrcheMind**。目录、口号、铁律在定名时锁定。用户确认后，助手给出了 V01 裸图的可运行草稿（`graph_model.py`、`build_v01.py`、`visualize_v01.py`）。那是开工样例，不是已经在本仓库里实现的代码。

## 架构结论

OrcheMind 是个人使用的通用本体系统，不限于 PCB。PCB 只是解释「穿过」这类关系的例子。哲学侧的判断类型是有限的；弹簧公式和 RC 电路在这套逻辑里可以落在同一种关系上。创造性代码生成留给大模型，本体负责可追溯、可校验的那一层。

三层在工程上的含义：

1. **始基本体（根）**  
   符号图是可信源。顶层是康德的量、质、关系、模态，其下十二范畴。空间关系先挂 RCC8，再扩展工程动词。全局实体 ID 是跨会话地址。这一层不从代码反推，也不交给梯度改写。

2. **进化迭代（体）**  
   版本是图的增量，不是把整个项目重新塞进上下文。V01 裸拓扑，V02 类型与端口，V03 才是角度、簇原型和嵌入。每个快照只读。

3. **对齐大模型（用）**  
   粗定位与精确谓词在本体侧完成，只把命中的实体、约束和少量上下文交给千问。`W_align` 连接两个空间。模型输出若要回流，仍只能按残差规则小改，不能覆盖顶层 Schema。

明确不做：

- 不改千问或任何开源模型的 RoPE，不把内部 K 缓存当成实体指纹。
- 不微调大模型。
- 不把代码知识图谱当成权威源。
- 不加载 RotatE 在 WN18RR 上的预训练权重当作本体。
- 不在 V01、V02 里做向量、损失和训练。

## 开发铁律

1. **快照固化**。一个阶段完成，整份图复制进 `snapshot/`。存档只读，不删、不改。下一步只改工作副本。
2. **先验优先**。人工 Schema 高于学习结果。模型只做裁剪过的残差，不许打散范畴簇和预先分配的角度。
3. **双轨并存**。粗轨是人定义的簇，用来快速定位；细轨是每个动词自己的角度，用来精确匹配。粗轨不靠训练才存在。
4. **算力分工**。4060 训练本体小模型；Mac 管本体与预处理；公网千问只推理。本体规则留在本地 Schema。
5. **正向驱动**。Schema 生成并约束实例；实例变更只通过校验后回写。大模型不能直接改 Schema。

- 公网千问：V01 用不到。

## 现在就做的 V01

V01 名称：`v01_raw_graph`。没有端口，没有类型，没有方向，没有向量，没有训练，不需要 GPU。

数据模型：

- **Node**：`id`，`name`。
- **Link**：`id`，`source_id`，`target_id`。
- 图可以存成 JSON，也可以从 JSON 读回。

第一张图只挂这些节点，并用无类型连线把它们接起来：

- 四大类：量、质、关系、模态。
- 十二范畴：单一性、多数性、全体性；实在性、否定性、限制性；实体与偶性、因果性、协同性（共存）；可能性、存在性、必然性。
- RCC8 八个关系，全部挂在「协同性（共存）」下面：DC、EC、PO、EQ、TPP、TPPi、NTPP、NTPPi。

做完要满足：

- `networkx` 能加载，节点和连线不重复，该连上的是连通的。
- JSON 写在 `data/ontology_graph/`。
- 把这一版完整复制到 `snapshot/v01_raw_graph/`，并写一句版本说明。此后这份快照不再修改。

V01 不加入焊盘、通孔等领域实体。那些是以后的例子，不是第一张图的内容。第一张图先把哲学范畴和 RCC8 的裸拓扑跑通。

## 其后顺序（现在不实现）

**V02 `v02_typed_link`**  
在 V01 拓扑上增量：Link 增加 `link_type` 与 `directed`；Node 按关系类型分化 Port；一种 Link 只能接入对应 Port。谓词开始与动词、范畴簇绑定。可导出 OWL，在 Mac 上用 Protégé 看。仍然不训练。完成后快照为 `snapshot/v02_typed_link/`。

**V03 `v03_embedding_base`**  
才给谓词分配复平面初始角度和簇原型，准备三元组，在 4060 上训练带残差和四项损失的 RotatE 变体，并用公网千问的 token 嵌入训练 `W_align`。失败就回滚到 V02，不改 V02 的图拓扑。

再往后才是谓词扩到通用领域、运行时三段检索，以及「模型输出经校验后回流本体」的闭环。

## 开工含义

讨论已经足够支持动手。下一步不是再展开理论，而是在本仓库按上面的目录建立 V01：裸的 Node 与 Link、康德十二范畴、RCC8 八个节点、JSON 持久化、快照固化。

向量、损失、对齐矩阵、公网千问、Protégé 导出，都排在这张裸图冻结之后。
